## 一、数据源

两个免费公开接口，都不需要 token。

### 1. 新浪 5 分钟 K 线（主数据源）

```
https://quotes.sina.cn/cn/api/json_v2.php/CN_MarketDataService.getKLineData
    ?symbol=sh510300&scale=5&ma=no&datalen=1250
```

返回 JSON 数组，每根 K：

```json
{"day":"2026-11-04 09:35:00","open":"4.086","high":"4.109","low":"4.062",
 "close":"4.100","volume":"79993600","amount":"328140413.1729"}
```

关键点是 **`amount` 字段（成交额，单位元）**。一天 48 根求和就是当天精确成交额，不需要用「成交量 × 均价」近似——这一步直接决定 20 日均额准不准。

`datalen=1250` 约 26 个交易日（一天 48 根），够 20 日基准再加冗余。给太大（比如 2000）会返回 `null`，别贪。

备用写法（json 版偶尔返回空）：

```
https://quotes.sina.cn/cn/api/jsonp_v2.php/var%20_=/CN_MarketDataService.getKLineData?...
```

返回 `var _=([...]);`，把前缀和末尾分号切掉再 parse。

### 2. 腾讯行情快照

```
https://qt.gtimg.cn/q=sh510300,sh510310,sz159915
```

一次可以请求几十个代码，`~` 分隔，**GBK 编码**，不是 JSON，字段全靠位置索引：

| 索引 | 含义 | 备注 |
|---|---|---|
| 1 | 名称 | |
| 2 | 代码 | |
| 3 | 现价 | |
| 4 | 昨收 | |
| 6 | 成交量（手） | |
| 7 | 外盘（手） | 成交在卖价 = 主动买 |
| 8 | 内盘（手） | 成交在买价 = 主动卖 |
| 30 | 时间戳 | `20261105103105`，前 8 位是日期 |
| 32 | 涨跌幅 % | |
| 37 | 成交额（**万元**） | 注意单位 |
| 38 | 换手率 % | |
| 45 | 总市值（亿元） | ≈ 价格 × 份额 |
| 72 | 场内份额（份） | 沪市是 T+1 |

前端在浏览器里用 `<script src="https://qt.gtimg.cn/q=...">` 直接加载，腾讯会自动包成 `v_sh510300="..."` 的全局变量，等于现成的 JSONP，不用处理跨域。

### 3. 持仓名单（静态写死，不是实时数据）

`update_data.py` 顶部 `ETFS` 列表里 `huijin` 那一列，是 2025 年报口径的前十大持有人份额（亿份）。

这是**最后一次公开实名披露**：2026-03-13 证监会修订的信息披露准则第 2 号自 2026-05-01 起施行，删除了上市基金列示前十名持有人的强制条款，中报、三季报都不再披露。

所以这一列是历史标签，不是当前持仓。留空也能跑，页面显示 `—`。

## 二、四个算法

### 1. 20 日均额基准

```
avg20 = mean(快照交易日之前 20 个完整交易日的成交额)
```

注意是**之前**，不含当天——当天要跟基准比，自己不能进基准：

```python
base_days = [d for d in full if d < trade_date][-20:]
```

### 2. 同时点对齐（盘中能不能读全靠这个）

上午 10:30 的成交额只是半天，直接除以「全天 20 日均额」得到的倍数毫无意义——它必然小于 1，然后你会得出「今天没量」的错误结论。

做法：

1. 取近 20 个交易日每根 5 分钟 K，算出每天的「累计成交额 / 全天成交额」曲线（48 个时点）；
2. 对同一时点跨天取均值，得到标准日内进度曲线 `shape`；
3. 盘中查表：`shape['10:30'] ≈ 0.31`，意思是历史上 10:30 平均已经走完全天的 31%；
4. 分母 = `avg20 × 0.31`，分子 = 当前累计成交额，两者都是「到此刻为止」，可以直接比。

收盘后进度 = 1.0，公式退化成普通倍数。所以盘中看到的是「同时点倍数」，收盘看到的是「较 20 日均额」，这两个数不能混着比。

### 3. 主动净买入

```
净买入 = (外盘 − 内盘) ÷ (外盘 + 内盘) × 成交额
```

这是**逐笔成交方向的推算**，不是资金净流入，不是申赎，不含大宗交易。ETF 有一二级市场套利，同一笔申购会在二级市场产生反向卖出，会稀释这个信号。

代码里有个细节：拿不到外盘/内盘时返回 `null` 而不是 `0`。返回 0 会被读成「买卖力量相等」，把结论往「方向不清」上带——这是两种完全不同的结论。

### 4. 尾盘占比

```
尾盘占比 = 14:35–15:00 成交额 / 全天成交额
```

跟 20 日均值比。这个指标能区分两种完全不同的放量：

- 尾盘占比**升高** + 放量 → 收盘前托底，符合护盘形态；
- 尾盘占比**下降** + 放量集中在早盘 → 情绪抢筹、开盘冲进去，性质完全不同。

它是最便宜、也最有效的「真护盘 / 假护盘」区分器，所以页面把它写进结论文字，而不是当附注。

## 三、三个必踩的坑

### 坑 1：沪市份额是 T+1

今天收盘跑脚本，拿到的沪市 ETF 份额是**昨天**的。深市通常当天就有。

后果：每天只跑一次的话，沪市那几只的「份额变化」永远是 0——两天的快照拿到的都是同一天的值。解法就是每天跑两次（09:45 补份额、15:30 拿量价）。

页面加了自检：**同一市场 ≥70% 的标的份额两日完全相同时，整片标「份额源未日更」而不给数字**。「整片市场同时不动」不可能是真实申赎，那是数据源没更新。

### 坑 2：外盘/内盘只在当天有效

腾讯快照里的外盘内盘是「今天」的累计值。今天收盘不跑，明天再跑这个字段已经翻到新的一天了，昨天的主动净买入永久丢失。

所以必须在交易日 15:30 之后跑。脚本的兜底：发现上一份快照是同一交易日且带外盘内盘时，沿用不清零。

### 坑 3：快照日期和实时报价日期会打架

盘中打开页面，快照是昨天收盘的，实时报价是今天的。直接拿今天的成交额去比昨天的 20 日均额，倍数全错。

代码里的规则：

- 实时报价日期 **>** 快照日期 → 进入实时口径，用实时成交额，分母按同时点进度缩小；
- 实时报价日期 **=** 快照日期 → 只在交易时段用实时值（16:00 后收盘价和快照一致）；
- 实时报价日期 **<** 快照日期（断线、缓存）→ 一律用快照。

写数据脚本时同理：只有 `实时日期 == 快照交易日` 才允许用实时成交额覆盖，否则会把「今天的盘中成交额」记到「昨天收盘」那一行上。

## 四、页面怎么搭的

没有框架、没有构建、没有 npm。

- **数据入口**：`<script src="data/snapshot.js?t=时间戳">`。加时间戳是为了绕浏览器缓存——这文件天天变，缓存住就完了。
- **实时叠加**：快照渲染完后，再用 JSONP 拉一次腾讯行情，覆盖到内存里的 `LIVE` 对象，整体重渲染。20 秒一次，收盘后停止。
- **图表**：手写 SVG 字符串。柱状图是 `<rect>` 循环，折线图是拼 `M/L` 路径。为两张小图引 ECharts 不值得。
- **表格**：字符串拼接 + `innerHTML`，20 行不需要虚拟 DOM。
- **迷你走势**：每行 30 个 `<i>` 元素高度按比例，就是「近 30 日成交额」那一列。

判定引擎就是个四象限，阈值在 `index.html` 顶部的 `CFG`：

```js
var CFG = {
  hotRatio: 1.80,   // 强信号
  midRatio: 1.30,   // 弱信号
  ...
};
```

## 五、试过但没用的方案

| 方案 | 为什么放弃 |
|---|---|
| 腾讯日 K 拿成交额 | 频繁 501，稳定性不如新浪 5 分钟 K。基准完全走新浪，腾讯只用于实时叠加 |
| 用「成交量 × 均价」估算成交额 | 均价不等于成交额加权均价，20 日均额会系统性偏差。新浪直接给 `amount`，没必要近似 |
| 拿不到外盘内盘时填 0 | 0 会被读成「买卖力量相等」，与「数据缺失」是两个结论。改成 `null` + 独立分支 |
| 用日度份额变化直接代表国家队 | 申赎方可能是任何机构，只能当粗近似。页面上写清楚，不硬拗 |
| 引入前端框架 / 图表库 | 两张小图 + 20 行表格，手写 SVG 几小时搞定，引库反而增加维护面 |

## 六、口径的正确读法

几个容易混的地方，写下来省得反复解释：

1. **倍数**是「成交额 / 20 日均额」，不是「成交量 / 20 日均量」。放量看金额更准，因为价格在变。
2. **盘中倍数**已按同时点折算，跟收盘倍数不是一回事，不能跨时点比较。
3. **净买入**是推算的主动买卖差，不含大宗交易，不含申赎。它的价值在符号和背离，不在绝对值。
4. **份额变化**是场内份额，沪市 T+1。它反映一级市场申赎，跟二级市场成交是两码事。
5. **加仓指数**是相对值，起点由你第一次运行的时间决定，不同人跑出来的曲线不能直接比。
