## 2026-11-05 · v1.0 首次完成

一天做完三件事，工具从零到可用。

**上午 · 方法确立**

- 确定 20 只宽基 ETF 的标的池与 `core` 分组，权重品种单列
- 定下四个指标：成交额放大倍数、主动净买入、日度份额变化、尾盘占比
- 判定引擎做成四象限，阈值 1.8× / 1.3×

**中午 · 数据管线**

- `update_data.py` 完成，415 行纯标准库，20 只全量约 25 秒
- 解决同时点对齐：用 20 日平均日内进度曲线折算盘中成交额，否则盘中倍数永远小于 1
- 拿不到外盘/内盘时返回 `null` 而非 `0`，判定引擎加「缺方向」独立分支
- 加份额源自检：同一市场 ≥70% 标的份额两日不变时，整片标「份额源未日更」而不给数字

**下午 · 页面与验证**

- `index.html` 完成，HTML/CSS/JS 全内联，零依赖
- 修两处图表缺陷：`preserveAspectRatio="none"` 导致文字被拉伸、均额标注与柱子重叠
- 无头浏览器渲染验证、`node --check`、DOM 桩冒烟测试全部通过
- 核心三数核对：池内合计成交额 838.8 亿 / 20 日均额 481.8 亿 / 放大倍数 1.74×，与独立复算一致

**同日 · 一个方法上的发现**

用 2026-11-04 做反例，确立了「放量 ≠ 护盘」的判读方法：那天放量 1.74×、净买入 +184.51 亿，但池内加权涨跌 +3.71%、涨幅集中在中证1000 与科创50，沪深300 仅 +2.0%、上证180金融ETF 反而 −0.73%，尾盘成交占比 13.1% 低于 20 日均值 17.0%。结论是情绪修复性放量，不是权重托底。

这条判读逻辑后来写进了 README 的示例和页面的结论文字——**单看倍数会误判**，是这个工具最需要提醒的地方。

## 后续计划

按有用程度排，都不保证时间。

| 项 | 说明 |
|---|---|
| 失败告警 | `deploy/run_once.sh` 顶部有 `WEBHOOK_URL`，填企业微信/钉钉机器人地址即可。接口悄悄挂了一周才发现，是这类小工具最常见的失效方式 |
| 补历史份额 | 现在只能从自己第一次运行那天积累。要补齐更长的份额曲线，得逐日抓交易所的基金份额公告，工作量大且接口无官方文档 |
| 页面内「立即更新」按钮 | 加个小接口触发 `update_data.py`，盘中不用等定时任务。代价是多一个常驻进程和一处攻击面，等真的觉得痛再加 |
| 数据备份自动化 | 份额历史丢了没有任何渠道能补，`deploy/backup.sh` 已就位，接上对象存储即可 |
