# 01 使用与部署

## 环境要求

- Python **3.6+**，只用标准库（`json` / `os` / `sys` / `time` / `urllib`），不需要 pip 装任何东西
- 任意浏览器（页面是纯静态 HTML + 内联 JS）
- 能访问 `quotes.sina.cn` 与 `qt.gtimg.cn`

Windows 直接双击 `app/run_daily.bat` 也能跑，等价于 `python update_data.py`。

---

## 每日怎么跑

```bash
cd app

python update_data.py --test    # 只跑前 3 只，验证接口通不通，约 3 秒
python update_data.py           # 全量 20 只，约 25 秒
```

跑完打开 `index.html` 即可，不需要起服务。

### 为什么要跑两次

| 时间 | 拿到什么 | 为什么 |
|---|---|---|
| **09:45 之后** | 昨天收盘的沪市份额 | 沪市份额是 T+1 的，不补这一次，份额变化永远是 0 |
| **15:30 之后** | 当天完整量价 + 外盘内盘 | 外盘/内盘是当日累计值，隔天就翻篇，昨天的主动净买入永久丢失 |

只跑一次也能用，但份额那一列会一直是 0。脚本做了兜底：发现上一份快照是同一交易日且带外盘内盘时，会沿用而不是清零。

非交易日跑会沿用上一份快照，不会写坏数据。

### 挂定时任务

Linux（`/etc/cron.d/etf-watch`，注意**文件名不能带点、权限必须 644**，否则 cron 静默忽略）：

```
45 9  * * 1-5 root cd /opt/etf-watch && python3 update_data.py >> logs/update.log 2>&1
35 15 * * 1-5 root cd /opt/etf-watch && python3 update_data.py >> logs/update.log 2>&1
```

Windows 用「任务计划程序」，触发器设两个时间点，操作指向 `run_daily.bat`。

## 部署到服务器

纯静态，任何能放文件的地方都行。要固定域名访问，用 nginx：

```bash
# 1. 目录
mkdir -p /opt/etf-watch/logs

# 2. 上传（注意带上 data/，否则份额历史清零重来）
scp -r index.html update_data.py deploy data user@your-host:/opt/etf-watch/

# 3. 权限
cd /opt/etf-watch
chmod 644 index.html data/*.js data/*.json
chmod +x deploy/run_once.sh deploy/backup.sh

# 4. 试跑
python3 update_data.py --test

# 5. nginx + 口令
cp deploy/nginx-etf-watch.conf /etc/nginx/sites-available/etf-watch
ln -sf /etc/nginx/sites-available/etf-watch /etc/nginx/sites-enabled/
htpasswd -c /etc/nginx/.htpasswd etf
nginx -t && systemctl reload nginx
```

`deploy/` 里四个文件：

| 文件 | 用途 |
|---|---|
| `nginx-etf-watch.conf` | 反代/静态站配置，含 `noindex` |
| `etf-watch.cron` | 上面那两条定时任务 |
| `run_once.sh` | 跑批包装，带日志与失败告警钩子 |
| `backup.sh` | 把 `data/` 打包传对象存储 |

**两层都要放通端口**：机内防火墙（`ufw allow 8080/tcp`）+ 云控制台安全组。只开一层是最常见的坑。

验收：

```bash
curl -I http://127.0.0.1:8080/                # 401
curl -u etf:<口令> -I http://127.0.0.1:8080/   # 200
```

## 想改什么，改哪里

| 想做的事 | 改哪里 |
|---|---|
| 换标的池 / 加减 ETF | `update_data.py` 顶部 `ETFS` 列表：代码、名称、指数、分组 |
| 改判定阈值 | `index.html` 顶部 `CFG`（`hotRatio: 1.80` / `midRatio: 1.30`） |
| 改结论文案 | `index.html` 的 `verdict()`，五个分支对应五种量价组合 |
| 加指标（换手率、溢价率等） | `update_data.py` 里 `items.append(...)` 加字段；字段索引见 `02_指标口径与实现.md` |
| 份额历史起点 | 从第一次跑脚本那天开始积累，无法回溯 |

三个主要常量在 `update_data.py` 顶部：

```python
LOOKBACK_DAYS = 20      # 均额基准窗口
BARS_PER_DAY  = 48      # 5 分钟 K，一天 48 根
TAIL_START    = "14:35" # 尾盘起点
```

## 常见问题

**跑完页面显示「找不到 data/snapshot.js」**
`data/` 没跟着上传，或者文件权限不对。`chmod 644 data/*` 再刷新。

**倍数明显不对（比如 0.02×）**
八成是盘中跑的。盘中成交额只是半天，必须按同时点进度折算——脚本已经做了，但如果 `data/snapshot.js` 的日期和实时行情日期对不上，会退化成直接比。看顶部状态标签是不是「盘中」。

**份额那一列全是 0 或全是「—」**
两种情况：只跑了一次（缺 09:45 那次），或者数据源当天没更新。页面有个自检：同一市场 ≥70% 的标的份额两日完全相同时，整片标「份额源未日更」而不给数字——「整片市场同时不动」不可能是真实申赎。宁可不说，也不要说错。

**接口超时**
先单独验证：

```bash
curl -sI "https://qt.gtimg.cn/q=sh510300"
curl -s "https://quotes.sina.cn/cn/api/json_v2.php/CN_MarketDataService.getKLineData?symbol=sh510300&scale=5&ma=no&datalen=100" | head -c 200
```

两个都通说明是本地网络问题；新浪通、腾讯不通就只影响实时叠加，快照仍能生成。

**加仓指数图是空的**
正常。它从你第一次跑脚本算起，跑满 20 个交易日才有形态。

## 备份

份额历史只能靠每天准点抓一点点长出来，**机器丢了能重买，这份历史丢了没有任何渠道能补**。

`deploy/backup.sh` 每天把 `data/` 打包上传对象存储，改顶部 `OSS_BUCKET` 即可（阿里云 OSS / 腾讯 COS / 华为 OBS 都行，换一行命令）。嫌麻烦的话，定期 `scp` 回本地也比不备份强。
